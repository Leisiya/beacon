账务口径确认（2026-10-25）：经营看板以 CNY 汇总；保留每笔原币金额、交易时汇率及来源，客户额度单独记录。人工收款是资金流入，不直接计为消费收入或利润。

额度消费顺序确认（2026-10-26）：用户选择“赠送额度优先”，同一客户先消耗可用赠送额度，再消耗购买额度。此为后续来源分配的业务要求，当前钱包仍为合并余额，尚未实现分来源扣减；不能把现有用量直接认作付费消费收入。每次消费需保存实际来源分配，失败/取消的额度释放应恢复对应来源。

人工账务首个实现范围：

- `receipt` 记录确认实收及购买额度；`gift` 仅记录免费额度，不增加实收款。
- `refund` 记录已在站外确认的整笔退款，扣回原单全部额度；额度不足时整笔事务失败。退款保存自身发生时汇率和依据。当前不支持部分退款，也不会调用支付渠道转账。
- `reversal` 为记错账后的反向流水，保留原单，按原单原币金额、CNY 金额及额度精确反向记账。同一原单只允许一笔退款或冲正，尚未开放冲正后的更正重入账流程。
- 原币金额和 CNY 金额存整数分；汇率存十进制字符串。暂支持 CNY、USD、EUR、HKD；CNY 汇率必须为 1，其他币种要求填写交易时汇率及来源；不自动取今日汇率重算历史。折算到 CNY 分时只做一次四舍五入。
- 客户额度保持独立整数；账本注明购买/赠送来源，尚未实现消费时的购买/赠送额度归属，也不以这张账表推导消费收入或毛利。
- 幂等键绑定规范化后的请求内容和操作人；相同键、不同内容会拒绝。支付方式及交易参考号组成防重标识，参考号统一去首尾空白和小写；原单冲正后防重记录仍保留。
- 过账仅允许启用中的 Root 操作人；HTTP 接口另要求浏览器登录态与绑定全部规范化字段的一次性安全凭证，拒绝个人访问令牌。已启用第二因素时不能降级使用密码。仅支持无 Redis、无批量写入的同步数据库额度模式；财务/运营/技术细分授权待实现。
- 管理页按客户 ID 筛选、按 ID 游标分页；详情显示原币、汇率、CNY、原始额度单位、操作人、发生/记账时间和更正关联。退款和冲正从原记录发起。网络结果未知时锁定原请求并用新凭证重试；后续授权错误也不丢弃原请求。不要通过刷新页面重新开单。
- 账表与页面不包含历史充值、成本或消费收入，也不计算毛利；新增记录不会实际调用银行或支付机构转账。

资金总览（2026-10-26）：

- 2026-11-22 起并入“账本”的概览与客户标签（客户付款按时段汇总已保存的 CNY）；本节口径仍适用于后端 `view=cash_summary` 接口。
- 按 `occurred_at` 归属北京时间自然日；结束日期包含当日，今天截至查询时刻。退款、冲正保留在各自发生日期，不删除或回写原记录的历史归属。
- 实收、退款、带符号的冲正分别汇总已保存的 CNY 整数分；登记现金净额 = 实收 − 退款 + 冲正调整。赠送无现金，单列登记笔数。历史汇率不重新计算。
- 单次数据库查询提供一致读取，服务端流式精确累加，汇总金额通过十进制整数字符串传输；页面精确显示分，不受 JavaScript 安全整数限制。请求限时 10 秒，失败时显示错误，不能显示虚假零值或部分总额。大规模历史账本的性能仍需后续验证。
- 只反映本人工账本已录入的数据，不等于全站现金余额、消费收入、上游成本或利润；补录历史事项会更新其发生期间的查询结果。本轮未修改钱包、过账规则或数据库结构。

消费归属接入约束（2026-10-26，设计依据，尚未启用）：

- 上游 `RecordConsumeLog` 可通过配置关闭，写入失败只记录错误，日志还可按保留期删除；不能将它单独用作不可丢失的资金来源账。财务归属记录需与主库额度变动有一致性保证，调用日志仅提供关联与排查信息。
- 当前 `BillingSession` 的预留、补扣、结算及失败释放均需保留来源；实际用量等于预留时也必须形成完成记录，不能只在差额不为零时记账。重试共享同一调用的归属，异步任务须保存提交时预留关系。
- 用户已确认先赠送后购买。不得按照现在的用户分组或最新价格回算旧调用；购买、赠送及来源不明的历史额度要分别处理。旧合并余额无法可靠还原来源时标为待核对，不能默认算购买收入或赠送成本。
- 同一次客户调用可能跨赠送和购买来源，需要保存实际分摊，不能给整次调用粗略贴一个付费标签。自用及朋友使用的业务归属还需独立记录，不能仅依据是否收到现金或是否发放赠送额度推断。
- 购买额度的消费金额应基于对应入账批次的实收、折算快照与额度，使用累计分摊差额避免反复四舍五入损失；尚未消费的购买部分与赠送余额分别展示。现有整笔退款只检查合并可用额度，分来源退款约束需随该阶段一并完善。
- 采购价与客户价格独立；缺失采购快照时为待核算，估算与确认值区分，供应商余额差异不自动摊成成本。归属实现前继续保留看板“待接入”状态。
